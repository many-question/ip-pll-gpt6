# RT4低端调谐修正候选
更新：2026-10-13T14:22:49+08:00

独立4.8fF RT4候选新增456/672MHz完整PLL捕获通过，末1µs平均456.000009/672.000067MHz；连同此前336MHz，三个低端饱和点均已修正。三项均约56.504µs后持续qualified至64µs，锁定期间最差测频偏差6.821ppm。984MHz仍由原流水线运行，原4.4fF已采用基线保留。

三个完整PLL结果（第99、100次汇报）：独立复位捕获64µs，TT27/1.2V/24MHz/10fF、Spectre X AX、8ps/reltol1e-3、噪声关闭。原4.4fF在这三点粗码255、细调贴近低端，输出约343.7395/458.3474/687.5375MHz；新4.8fF候选恢复到目标频率并留有调谐余量。

三项均约53.586µs acquired、55.170µs frequency_good、56.504µs qualified，并保持到64µs；持续qualified窗口7.496µs、179次内部逐参考周期测频观察。最差频偏为336MHz点的6.821ppm。这是功能测频结果，不是抖动。

新增456/672MHz各32,001个物理波形点完整有限、raw END、退出码0、Spectre 0 errors；输入、raw、日志、终态本地/远端SHA-256一致，Newton/skipped/LTE为0。启动仍有已有AHDL环境警告和约1.2mV初始条件偏差通知，没有数值恢复。复位期间qualified低正常，未套用稳态失锁保护。

仅984MHz现有任务继续，使用4个请求线程。等其完成再决定必要的定向修正；本次无新增仿真，无方案替换。原4.4fF的216/240/288MHz通过结果不能与新候选三点合并为同一版本全频通过。

复核入口：`python share/deliverables/integration/cmos_v14_full/review_rt4_range48_capture.py CASE <新输出JSON路径>`。证据：[336MHz复核](results/rt4_range48_k14_review99.json)、[456MHz复核](results/rt4_range48_k19_review100.json)、[672MHz复核](results/rt4_range48_k28_review100.json)、[第100次终态与队列快照](results/rt4_range48_repair_review100.json)。

采用单独顶层 `pll_capture_rt4bank_range48_v14.scs`，只把VCO开关电容单元从4.4fF改成4.8fF。控制器、RT4、分频链、采样器、Q5电感模型、CF10和偏置保持；原顶层24项物理依赖哈希未变。新候选尚未替换已采用的RT4基线。

上述400ns局部夹具保留实际VCO/采样器/RF接收器/新分频链/RT4，外部钳位码与细调电压；用最后60ns的过零点测频。两项均Spectre退出0、raw END、真实进程已退出，输入及本地/远端raw、日志、终态哈希匹配，物理波形有限，Newton/skipped/LTE为0。它们本身仅证明两个端点可达；336/456/672MHz闭环证据见上，全码重叠仍未验证。旧4.8fF夹具结果没有移植为本次结果。

端点门限通过后，同一流水线启动336、456、672、984MHz四个此前未通过的频点，均64µs独立复位/apply、TT27/1.2V/24MHz/10fF、AX8ps/reltol1e-3、噪声关闭。初始4项各4线程、合计16；目前三个低端点已完成，仅984MHz一项4线程；不重跑原7+6队列，不新增33点/PVT/精度/种子矩阵。复位期间qualified低属正常，不触发稳态失锁保护。

既有984MHz记录已按MOS计数锁存和状态位解码。旧成功记录在粗码22测得1313，超过目标1312；本次AX记录测得1307，低于目标，所以SAR选择24/22的差异与计数一致。本次AX细调的DAC48/40/44/42/41对应计数5251/5240/5255/5258/5259，不满足稳定单调搜索的假设；选中的DAC48早期探测与交接后的频率也不同。确切原因尚未隔离，不能据此直接强制固定粗码。先观察同精度的新物理候选。

原RT4最差115.2fs只作原方案高偏移阶段依据，新电容候选尚未测噪声；最终10kHz至fOUT/2、排除离散杂散、RMS<200fs保持。功耗优化和版图仍后置。
